# Demo script

1. Copy `.env.example` to `.env`, then run `npm install`, `npm run seed`, and `npm run dev`.
2. Open http://localhost:5173 and sign in as `hr.manager@acme.test` / `Password123!`. Use Night and Day in the header. Sign in with the same account in a second browser and confirm the theme follows. A new tab does not reuse the session on its own. The sign-in page theme stays in that browser only.
3. Switch Language to Português. Navigation, filters, and the directory labels change. Department and country values sent to the API stay English names and country codes. Switch back to English.
4. Open Profile from the header. The avatar shows the initials HM for HR Manager. Change the display name, save, and confirm the initials change, then restore HR Manager. Upload a PNG, JPEG, or WebP photo, then remove it. Leave the demo password as `Password123!`.
5. Search for `José`. Open `EMP-000001` and confirm the directory shows a current salary. Pagination sits at the top right of the directory, and the table scrolls in the space left on the page. Sort a column and click it again to reverse the order.
6. On Employees, open **Add employee**, save a person, then delete that row from the actions menu so the directory is unchanged. Open **Bulk Import Employees**. The templates, file, preview, and feedback download stay in that dialog. Download the CSV or Excel template. Upload a file with one new valid employee and one row whose department is not in the list. A Portuguese department such as Engenharia is valid and is stored as Engineering. Preview highlights the invalid row and writes nothing. Confirm. A dialog shows how many employees imported and how many failed, and it can be closed. Download the Excel feedback file and confirm each row has an import result and a feedback message. Search for the new employee and confirm the invalid row was not created.
7. Optional: upload the unchanged template. It creates `EMP-900001` (Ada Lovelace, with a hire salary) and `EMP-900002` (Grace Hopper, no salary). Upload that same template again and both rows are skipped as duplicates.
8. On an employee page, add a salary with an effective date after the latest history row. The form starts on the next valid date. Confirm the previous amount remains in the history table. A future effective date does not change the current salary until that date.
9. Open Audit and find the `SALARY_UPDATE` row for that employee. An import also writes `EMPLOYEE_IMPORT`, plus `SALARY_UPDATE` when the row included a hire salary. Creating or deleting an employee writes `EMPLOYEE_CREATE` or `EMPLOYEE_DELETE`.
10. Open Analytics. While the summary loads, the charts are replaced by a skeleton and the title stays. Group by department and confirm a small group shows `Suppressed` instead of a median. Executive employees in Canada are seeded as a group of three. The headcount, median, and distribution charts follow the selected currency and use the API figures. The country filter and seed also include Portugal, Brazil, Angola, Mozambique, Cape Verde, Guinea-Bissau, São Tomé and Príncipe, and Timor-Leste after a fresh seed.
11. Open Questions and ask `What is the median salary in India by department?`. The answer includes the filters, currency split, and the calculation definition. `What is the median salary in Portugal by departamento?` resolves to the same kind of answer for country `PT`.
12. Ask `Delete all salaries`. The page shows a rejection and no salary figures.
13. Sign out and sign in as `directory.user@acme.test`. The directory has no salary column, no add button, and no bulk import. Analytics, Questions, and Audit are not in the navigation. Profile, language, and theme remain available. `hr.viewer@acme.test` can read salaries and analytics, and cannot import or update. `auditor@acme.test` can open Audit and salary history, and cannot import.
